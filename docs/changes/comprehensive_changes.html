종합 분석 · comprehensive.py — API 계약 정합화

강점·냉정 진단 통합 종합 분석기의 반환 형식을 공통 envelope로 통일했습니다.

대상: comprehensive.py 기능: 종합분석 근거: §3.3[1] · §3.6 · #25 · #26 출력 내용 불변
🎯 대원칙 — 출력 내용(분석 결과·자소서 본문·레쥬메 필드 값)은 한 글자도 바꾸지 않았습니다. 백엔드·프론트가 공유하는 반환 형식(envelope)만 계약 문서에 맞춰 통일했습니다. schema_version은 문서 §3.5에 따라 tasks.py(백엔드)가 주입하므로 이 파일에는 넣지 않았습니다.

1. main()이 payload를 그대로 print하던 문제

문제main()이 json.dumps(result)로 payload(검증된 채용공고·강점/약점 진단 포함)를 그대로 출력하고 반환하지 않았습니다. 최상위 status·vector 봉투가 없었습니다. 계약 §3.3 [1] analyzer 반환 shape

해결검증(자격증·동아리·공모전·채용공고)까지 끝난 result를 envelope {status, result, vector}로 감싸 return. 검증 결과(verified_jobs 등)는 payload에 그대로 보존.

Before

# ... 검증 끝 ...
print(json.dumps(result,
  ensure_ascii=False, indent=2))
# ← 봉투 없음, return 없음

After

payload = {k:v for k,v in result.items()
           if k != "status"}
envelope = {"status":"success",
            "result":payload,
            "vector":vector}
return envelope

2. status·vector 유출 방지 (개별·종합이 가장 위험)

문서 §3.6은 개별·종합을 가장 위험하다고 표시합니다 — 이 두 타입만 envelope에 vector를 싣기 때문에, internal.py를 단순히 analysis.result = result로 바꾸면 result 안에 vector·status가 그대로 실립니다.

문제payload 최상위의 status가 저장·노출되고, vector가 result에 섞일 수 있음. 계약 §3.6 #25·#26, §3.3 위험 경고

해결payload에서 status 제거 → envelope 최상위. vector는 별도 필드로만. 덕분에 상류(analyzer)에서 shape 차이를 없애 internal.py가 판단 없이 한 줄로 대입 가능.

3. 짧은 입력 처리

문제10자 미만 입력 시 error를 print만 하고 return(None). 계약 §3.3 실패 shape

해결return error_result로 실패 envelope 반환.

insufficient_data 등 '분석은 완료했으나 데이터 부족' 결과는 내용 보존을 위해 성공 envelope로 감싸 payload 안내 문구가 유실되지 않도록 했습니다. 분석 로직·프롬프트·검증 파이프라인은 불변입니다.
