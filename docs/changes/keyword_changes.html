1. 최상위 키 A_~F_ 순서 접두사 — 사고 #4의 직접 원인

문서 §3.4: 접두사는 사람이 읽을 때의 순서 표기일 뿐 데이터의 일부가 아닙니다. JSON은 키 순서를 의미로 갖지 않으므로, 섹션 하나만 추가돼도 뒤 키 이름이 연쇄로 바뀌어 프론트가 조용히 깨집니다. v4.1 머지(18:43) 후 프론트는 접두사 없이 읽어 배포되면 전 섹션 백지가 됩니다.

문제result 최상위 키가 A_keyword_definitions … F_improvement_guide로 접두사를 달고 있었고, 프롬프트 스키마·prose 지시·리더 함수(_enrich_and_tag_result, print_result_summary)가 모두 이 이름에 묶여 있었습니다. 계약 §3.4 (접두사 금지) · 사고 #4

해결6개 최상위 키에서 접두사를 전면 제거했습니다. 프롬프트 JSON 스키마, prose 참조, 후처리·요약 출력 코드까지 한 번에 맞춰 이름 불일치가 남지 않게 했습니다. 중첩 키(compliance_criteria·matched_criteria·key_quotes)는 접두사가 없으므로 그대로 유지.

2. result 안 status 제거 · main() envelope 반환

문제keyword payload는 _call_model()이 넣은 status를 최상위에 갖고 있었고, main()은 {careers, result}를 반환해 백엔드 계약과 달랐습니다. 계약 §3.3 [1] · §3.6 #26

해결payload에서 status 제거 후 envelope {status, result}로 반환. 키워드 테이블엔 vector 컬럼이 없으므로 vector 필드도 없습니다(§3.2).

Before

def main(...):
    ...
    result = analyze_keywords(...)
    return {"careers": careers,
            "result": result}

After

def main(...):
    ...
    result = analyze_keywords(...)
    payload = {k:v for k,v in result.items()
               if k != "status"}
    return {"status":"success",
            "result": payload}
접두사 제거는 '키 이름' 형식 변경일 뿐, 각 섹션의 분석 내용(정의·coverage 수치·스토리라인 등)은 v4.1 명세 그대로 100% 보존됩니다.
