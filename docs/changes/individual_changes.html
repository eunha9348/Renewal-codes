분석·Export API 정합화 · 변경정리

개별 분석 · individual.py — API 계약 정합화

단일 경력/자격증/활동 심층 분석기의 반환 형식을 공통 envelope로 통일했습니다.

대상: individual.py 기능: 개별분석 근거: §3.3[1] · §3.6 · #25 · #26 출력 내용 불변
🎯 대원칙 — 출력 내용(분석 결과·자소서 본문·레쥬메 필드 값)은 한 글자도 바꾸지 않았습니다. 백엔드·프론트가 공유하는 반환 형식(envelope)만 계약 문서에 맞춰 통일했습니다. schema_version은 문서 §3.5에 따라 tasks.py(백엔드)가 주입하므로 이 파일에는 넣지 않았습니다.

1. main()이 envelope를 반환하지 않던 문제

문제main()이 결과를 print만 하고 아무것도 return하지 않았습니다. tasks.py는 r = main(...)로 반환값의 status·result·vector를 읽어야 하는데 받을 값이 없었습니다. 계약 §3.3 [1] analyzer 반환 shape

해결main() 마지막에서 공통 envelope {status, result, vector}를 조립해 print와 함께 return하도록 변경.

Before

print(json.dumps(
  {"vector": vector, "result": result},
  ensure_ascii=False, indent=2))
# ← return 없음

After

envelope = {"status": "success",
            "result": payload,
            "vector": vector}
print(json.dumps(envelope, ...))
return envelope

2. result(payload) 안에 status가 섞여 나가던 문제

문제_call_model()이 돌려준 payload는 최상위에 status를 갖고 있어, 그대로 저장하면 data.result.status로 프론트에 노출됩니다. 계약 §3.6 #26 (result 안에 status 없음)

해결payload에서 status 키를 제거하고 envelope 최상위로만 올렸습니다. payload = {k:v for k,v in result.items() if k != "status"}

3. vector가 result 안으로 들어갈 위험

문제개별·종합만 벡터(3072차원)를 실어 주므로, 무심코 result에 함께 담으면 분석 1건당 ~60KB가 중복 저장되고 매 조회마다 프론트로 흘러갑니다. 계약 §3.2 · §3.6 #25 (result 안에 vector 없음)

해결vector는 envelope의 별도 필드로만 반환합니다. result(payload) 안에는 절대 넣지 않습니다. (개별·종합은 vector 필드 포함)

4. 짧은 입력 처리

문제입력이 너무 짧을 때 error 메시지를 print만 하고 return(None)했습니다. 계약 §3.3 실패 shape

해결return error_result ({status:'error', message})로 실패 envelope를 반환합니다.
