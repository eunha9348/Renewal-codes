main() 함수를 신설하고, 나머지 4종과 동일한 공통 envelope로 정렬했습니다.

대상: cover_letter.py 기능: 자소서 제작 근거: §3.3[1] (범위 밖·일관성 정렬) 출력 내용 불변
🎯 대원칙 — 출력 내용(분석 결과·자소서 본문·레쥬메 필드 값)은 한 글자도 바꾸지 않았습니다. 백엔드·프론트가 공유하는 반환 형식(envelope)만 계약 문서에 맞춰 통일했습니다. schema_version은 문서 §3.5에 따라 tasks.py(백엔드)가 주입하므로 이 파일에는 넣지 않았습니다.

1. main() 함수 자체가 없던 문제

ℹ️ 범위 안내 — 이 기능은 계약 문서에서 명시적으로 "범위 밖"으로 분류됩니다(arc-backend 전 브랜치에 코드 0건). 그럼에도 "5가지 기능을 모두, 모두 main()으로 종료" 요청에 따라 동일 형식으로 정렬했습니다.

문제엔트리포인트가 if __name__ == "__main__": 블록에 인라인으로만 있어 main() 함수가 없었습니다. 다른 4종처럼 main(...)으로 호출·반환할 수 없었습니다. 계약 §3.3 [1] · 사용자 요구(모두 main으로 종료)

해결파이프라인을 def main(...)로 감싸 신설하고, if __name__ == "__main__": main()으로 종료하도록 정리했습니다.

Before

if __name__ == "__main__":
    client = GeminiClient()
    result = generate_application(...)
    print(format_application(result))
    # ← main() 함수 없음, 반환 없음

After

def main(...):
    client = GeminiClient()
    result = generate_application(...)
    print(format_application(result))
    payload = asdict(result)
    return {"status":"success",
            "result": payload}

if __name__ == "__main__":
    main()

2. 공통 envelope 반환 + 예외 처리

문제반환 형식이 없어 백엔드 통합 시 다른 분석기와 계약이 어긋납니다. 계약 §3.3 [1] · §3.6 #25·#26

해결ApplicationResult(dataclass)를 asdict로 직렬화해 {status, result} envelope로 반환. 예외 시 {status:'error', message}. payload에는 status·vector가 없습니다.

자소서 생성은 계약 문서상 명시적으로 '범위 밖'(arc-backend에 코드 0건)입니다. 그럼에도 사용자 요청대로 나머지 4종과 동일한 반환 형식·main() 종료 구조로 정렬해 향후 통합 시 혼선을 없앴습니다. 자소서 본문·가이드·액션플랜 생성 내용은 불변입니다.
