레쥬메 · resume.py — API 계약 정합화

'영원히 생성 중'·'실패한 빈 레쥬메가 성공으로 보임'의 뿌리인 sys.exit(1)를 제거했습니다.

대상: resume.py 기능: 레쥬메 제작 근거: §2.4 🔴 · §3.3 · P0 #6 출력 내용 불변
🎯 대원칙 — 출력 내용(분석 결과·자소서 본문·레쥬메 필드 값)은 한 글자도 바꾸지 않았습니다. 백엔드·프론트가 공유하는 반환 형식(envelope)만 계약 문서에 맞춰 통일했습니다. schema_version은 문서 §3.5에 따라 tasks.py(백엔드)가 주입하므로 이 파일에는 넣지 않았습니다.

1. sys.exit(1) — 콜백조차 못 보내 result=null로 영구 방치

문서 §2.4는 레쥬메를 가장 급하다고 표시합니다. main()이 입력이 없으면 sys.exit(1)로 프로세스를 죽여 콜백조차 못 가고, 사용자에겐 '영원히 생성 중'으로 남습니다.

문제if not parts: print(...); sys.exit(1) — 실패를 표현할 방법 자체가 없었습니다. 계약 §2.4 🔴 · 수용기준 P0 #6

해결프로세스를 죽이지 않고 실패 envelope를 반환합니다. tasks.py가 이를 받아 /internal/resume/failure로 status=failed를 기록할 수 있습니다.

Before

parts = [...]
if not parts:
    print("ERROR: 입력 데이터 없음")
    sys.exit(1)   # ← 프로세스 사망

After

parts = [...]
if not parts:
    print("ERROR: 입력 데이터 없음")
    return {"status":"error",
            "message":"입력 데이터가 없습니다."}

2. main() envelope 반환

문제main()이 results(both) 또는 results[language](단일)를 그대로 반환해 봉투가 없었습니다. 계약 §3.3 [1]

해결{status, result} envelope로 감싸 반환. API 경계(ko|en)는 result=단일 레쥬메 payload. both는 문서상 경계 밖(§2.4)이라 CLI 편의용으로만 {ko,en} 묶음을 유지.

레쥬메 payload에는 원래 최상위 status가 없어 별도 제거가 필요 없습니다. language/status/title 컬럼 추가·PATCH·GET/{id} 등은 백엔드(스키마·라우트) 몫이며 이 파일 범위 밖입니다. 레쥬메 생성 내용은 불변입니다.
